# Forge numerical and import-graph executable gates — draft 2026-10-18

Issues #28 (typed numeric lowering beyond checked i64) and #31 (canonical project-root `+/` imports).

## Numeric invariants (#28)
- Distinguish checked signed i64 from IEEE f32/f64, exact decimal/bigint and matrix shapes in typed IR; no implicit runtime erasure.
- f32 and f64 preserve NaN/unordered comparisons, signed zero and infinity semantics, with explicit conversion/rounding rules.
- Decimal/bigint must not round-trip through a host floating point or 64-bit narrowing path.
- Matrix dimensions and element arithmetic must be checked; integer overflow and allocation extent overflow reject independently.

Vectors: `i64::MAX + 1` traps; `-0.0` retains signed zero under documented operations; NaN unordered; decimal `0.1 + 0.2` exact in decimal mode; `[2^62,4]` matrix extent rejects.

## Canonical import graph (#31)
- Resolve `+/` only relative to verified project root, never process CWD.
- Canonicalize and reject path traversal, symlink escape, shadowed package modules and path cycles before opening source.
- Import-time evaluation and ambient host I/O remain prohibited. Hash the exact dependency graph and place it in emitted artifact provenance.

Vectors: `+/src/foo` resolves within root; `+/../secrets` rejects; symlink outside root rejects; duplicate alias/identity resolves exactly one module; cycles fail with stable diagnostic.
