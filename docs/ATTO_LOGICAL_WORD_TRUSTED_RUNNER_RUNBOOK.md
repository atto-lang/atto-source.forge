## Security gate (before enabling)

1. Have an independent CODEOWNER review the **manual-only** workflow in Forge PR #246. It must remain on protected `main` before `workflow_dispatch` is available. Do not add a `pull_request` or `push` trigger to the self-hosted job.
2. An organization/repository administrator must check GitHub Actions settings, billing/spending restrictions, runner groups, labels and access to this **private** repository. The ChatGPT GitHub App cannot query billing, enumerate runners or register a runner. A job with `runner_id=0` and `steps=[]` is a *pre-runner admission failure*; it does not identify billing as the root cause.
3. Prefer an organization-managed, **ephemeral** dedicated VM (one job, destroyed and reprovisioned afterward), or equivalently strong isolated runner. Restrict its runner group to `ores-truffle-oreslang/oreslang-source.forge` only and give it labels `self-hosted`, `linux`, `x64`, **`atto-ci-trusted`**. Use a dedicated unprivileged runner account. Do not mount personal credentials, cloud identity, Docker host sockets, production secrets, or sensitive host volumes. Restrict outgoing network access to what GitHub API/checkout and approved dependencies require. Protect and expire registration credentials; never paste them into PR comments.
4. Use `config.sh --ephemeral` (or an equivalent just-in-time runner), preserve runner diagnostic logs under a protected retention policy, and **destroy the entire runner VM/image after this one job**. A runner merely disappearing from GitHub's inventory is not proof its filesystem was wiped. No long-lived shared runner is an acceptable default for this untrusted compiler toolchain.

Official GitHub background: [Manual workflow dispatch](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow), [ephemeral self-hosted runners](https://docs.github.com/en/actions/reference/runners/self-hosted-runners), [self-hosted runner security](https://docs.github.com/en/actions/reference/security/secure-use).

## Additional source-local security admission requirements (2026-11-10)

**An explicitly named runner group is required, not only labels.** An organization administrator must create group `atto-forge-source-local-trusted`, grant it **selected-repository access only** to `ores-truffle-oreslang/oreslang-source.forge`, then set **selected-workflow access only** to the exact reviewed `ores-truffle-oreslang/oreslang-source.forge/.github/workflows/atto-logical-words-source-local-trusted.yml@main`. Register the ephemeral runner inside that group with labels `self-hosted`, `linux`, `x64`, and `atto-ci-trusted`. A runner created in the default shared group MUST NOT be relabeled to masquerade as the trusted worker. GitHub documents runner-group selected workflow policies: https://docs.github.com/en/actions/how-tos/manage-runners/self-hosted-runners/manage-access

Before fetching or checking out the **target PR head**, the workflow's protected-main inline Python validates live GitHub REST PR identity, immutable repository ID `1419703674`, exact SHA/tree from the Git commit API, and **independent privileged `APPROVED` review explicitly bound to the exact PR head SHA**. The author cannot approve their own PR. Reviewer must be a non-author human GitHub account with an `OWNER`, `MEMBER`, or `COLLABORATOR` association **and independently verified effective `write` or `admin` permission on this exact repository** using the GitHub Collaborator Permission REST endpoint. Organization membership alone is NOT proof of write permission. The returned collaborator user ID must match the review author ID. Metadata access denial, read/triage role, wrong identity, bot, dismissed, prior-commit or self-review all fail closed; an existing approval is revalidated after the tests. A current-head `CHANGES_REQUESTED` review blocks admission. The workflow queries all review pages with a fail-closed cap, rechecks the same gate after tests, and refuses stale or moved-head tests.

The protected-main workflow first runs `python3 -m unittest discover -s verification -p test_atto_source_local_trusted_runner_gate.py -v` against its **own protected-main** inline gate, using synthetic mocked GitHub responses and no network. Only then does it checkout the reviewed PR SHA and build. This keeps tests of the admission policy outside the untrusted PR tree. Any gate/test mismatch fails the job before compiling the PR.
