# Checked unsigned Forge scalar candidate

An explicit, restricted source-to-C++20 compiler candidate, independent of the LLVM IR emitter but sharing the same bounded frontend design from [LLVM #1008](https://github.com/atto-lang/atto-source.llvm/pull/1008). No default Forge parser changes or fixture-specific translation. It accepts closed u64/uint functions, canonical literals, parameters, calls, grouping and checked +,-,*. It rejects recursive graphs, malformed signatures, out-of-range literals and excessive work before publishing output. Evaluation is emitted into ordered temporaries, preserving faults even when later arithmetic would cancel the result. Native output uses full-width uint64_t formatting, with explicit E_U64_OVERFLOW and exit 70 for this profile (not the general typed guest Error ABI).

Run node --test tests/checked_u64_forge_native.test.mjs with clang++ and g++. Local Node 22.16.0, clang 17 and GCC 14.2: 50/50 tests passed, 48 shared guest executions plus four non-corpus control executions across both C++ compilers at O0/O2, and 17 rejection controls. Exact compiler/test/corpus Git blobs matched local execution. This is not the full Forge native pipeline, production runtime ABI, hosted CI or general unsigned parity. The bounded frontend is duplicated temporarily; consolidate through the canonical typed frontend rather than maintaining separate grammars. Draft pending full tests and trusted review.

## Bounded unsigned division candidate

This extension admits truncating u64/uint quotient with explicit zero-divisor guard. The shared emitter uses a 64-iteration restoring division loop with carry-aware unsigned subtraction; no wide divide operation is required. The helper is emitted only for division-containing units. LLVM/Wasm use a generic terminal trap (not a distinct portable guest Error ABI); Forge emits exit 71 / E_U64_DIVISION_BY_ZERO, distinct from arithmetic overflow exit 70.

Exact compiler source blob `0fd2d7bf59912bd9182261bd4b3182da1655fa5e`; locally executed test `tests/checked_u64_division.py` blob `80772cbbff7e140935b7431edff31f7943fb8668`. Run on Linux AMD64 with Clang 17, Python 3, Node 22, wasm-ld and readelf: `ATTO_U64_DIV_SOURCE="$PWD/tools/forge_checked_u64.cpp" python3 tests/checked_u64_division.py`. Passed 48 independently compiled boundary guests (16 each native LLVM, native Forge with UBSan and wasm32), 512 dynamic emitted-Wasm-helper checks (256 each O0/O2), five malformed source refusals, and 12 LLVM cross-target objects at O0/O2 without unresolved arithmetic helpers. Cross-target objects are not native execution. Separately compared 768 nondivision source programs across both emitters (1,536 artifact comparisons); all byte-identical to blob `752d1ad3fb3564eed9067a0a530eb2150d1c14b4`. Existing historical conformance pins remain unchanged. No full-tree CI, canonical pipeline, fixed wall-clock WCET, 256 independently compiled division guests per native backend, or unified fault ABI claim.
